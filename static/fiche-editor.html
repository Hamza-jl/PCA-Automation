OBJ Objectif
L'objectif de ce document est de recueillir les besoins métiers en termes de continuité d'activité dans le cadre du projet du maintien en condition opérationnelle.

La phase d'identification des besoins métiers a pour objectifs de :
  • Inventorier les processus métiers et supports ;
  • Évaluer les contraintes de fonctionnement normal de chacun des processus (réglementaires, contractuels, confidentialité, déontologie, etc.) ;
  • Analyser les impacts d'arrêt de chacun des processus (image de marque, financiers, désorganisation interne, juridiques) ;
  • Déduire en fonction des contraintes de fonctionnement et des impacts d'arrêt le périmètre des processus critiques à secourir ;
  • Modéliser la chaîne d'activité de chacun des processus critiques.

Pour ce faire, les responsables des activités métiers doivent être rencontrés afin de déterminer les impacts et les besoins suite à un sinistre majeur.

§4 Description et criticité des activités métiers
Pour chaque processus :
  • Indiquer les ressources IT ou autres utilisées ;
  • Préciser les périodes critiques ;
  • Déterminer la criticité correspondante, à savoir :
    • Faible : L'activité correspondante peut être reportée pour une période relativement flexible ;
    • Moyenne : L'activité correspondante peut être reportée pour une période limitée ;
    • Forte : L'activité correspondante ne peut pas être reportée, elle doit être opérationnelle même de façon dégradée.

§7.2 — Collaborateurs clés
Par collaborateur clé on entend :
  • Tout collaborateur qui dispose d'une expertise rare/pointue ;
  • Tout collaborateur assurant une tâche tout seul ;
  • Tout collaborateur dont le potentiel d'encadrement est affirmé au sein de l'équipe.

§7.3 — Applications informatiques
Le tableau suivant représente les applications informatiques utilisées par l'entité ainsi que :
  • La criticité :
    • Vitale (V) : si le processus métier est arrêté en cas d'indisponibilité de l'application ;
    • Critique (C) : si le processus nécessite un travail manuel pour contourner l'application ;
    • Moyennement critique (MC) : si le processus métier nécessite un contournement de l'application indisponible par une autre application ;
    • Peu critique (PC) : si le processus métier est opérationnel et peu impacté ;
  • La DMIA — Durée Maximale d'Interruption Admissible : durée au-delà de laquelle une interruption de l'activité peut être préjudiciable pour la pérennité de l'entité et de l'entreprise ;
  • La PMDT — Perte Maximale de Données tolérée : durée maximale d'enregistrement des données qu'il est acceptable de perdre entre la dernière sauvegarde et le sinistre.
